# Technical Documentation — Local AI Second Opinion

Use `ask_local_ai` when creating or improving technical documentation.

Suitable outputs include:

- README
- Architecture documentation
- ADRs
- Runbooks
- API documentation
- Installation guides
- Troubleshooting guides
- Operational procedures

Documentation should be:

- Accurate
- Concise
- Reproducible
- Structured
- Version-aware
- Explicit about prerequisites
- Clear about risks

Never invent commands, configuration options or system behavior.

When documentation describes a current product, framework or cloud service, verify current official documentation when needed.

Prefer examples that can actually be executed or validated.
